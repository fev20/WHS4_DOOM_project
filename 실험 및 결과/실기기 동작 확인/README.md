# 실기기 동작 확인

실제 카메라에 수정한 펌웨어와 **WebSocket 방식의 DOOM 실행 파일**을 적용했습니다. 웹 로그인 화면의 리셋 버튼을 누르면 카메라에서 DOOM이 실행되고, PC 브라우저가 게임 화면을 받아 표시하도록 구성했습니다.

WebSocket은 연결을 유지하면서 데이터를 주고받는 통신 방식입니다. 이 구현에서 게임은 카메라에서 실행되며, PC 브라우저는 게임 화면을 표시합니다.

실행 구성은 다음과 같습니다.

```text
웹 페이지의 Reset 버튼
    → 카메라에서 SD 카드의 DOOM 실행
    → WebSocket으로 게임 화면 전달
    → PC 브라우저에서 화면 표시
```

버튼과 실행 스크립트의 자세한 구성은 [둠 트리거 구현](../../DOOM%20포팅%20구현/둠%20트리거%20구현/README.md)에서 설명합니다. 여기서는 이 구성이 실제 카메라에서 동작하는지 확인한 결과를 다룹니다.

## 1. WebSocket 방식의 게임 실행 확인

관리자 페이지의 리셋 버튼을 통해 DOOM을 실행하고 게임 페이지로 이동하는 동작을 확인했습니다. 브라우저에는 카메라에서 실행한 DOOM 화면이 표시되었습니다.

![WebSocket 방식의 실기기 시연에서 표시된 DOOM 시작 화면](./img/image%202.png)

최종 시연 영상에서 가져온 시작 화면입니다. 브라우저 주소는 실제 카메라의 `10.68.68.22:8081/index.html`입니다.

![WebSocket 방식의 실기기 시연 중 게임 화면](./img/image%203.png)

같은 시연 영상에서 게임 진행 중의 화면을 가져왔습니다. 초기 화면 표시뿐 아니라 게임 장면이 갱신되는 모습도 확인할 수 있습니다.

[실기기 최종 시연 영상](./demo.webm)

> 초기에는 BMP 이미지를 반복해서 가져오는 방식도 테스트했지만, 약 2fps로 화면 갱신이 느려 최종 시연에는 WebSocket 방식을 사용했습니다.

## 2. 확인 결과

| 확인 항목 | 결과 |
|-----------|------|
| 웹 버튼으로 실행 | Reset 버튼을 통해 DOOM 실행 및 게임 페이지 이동 완료 |
| 카메라에서 게임 실행 | SD 카드의 WebSocket 방식 바이너리 사용 |
| 브라우저에서 화면 확인 | 시작 화면과 게임 진행 화면 표시됨 |
| 화면 갱신 | 최종 시연에서 게임 장면 갱신 확인, 정확한 fps 측정값은 없음 |

이번 확인은 실기기 실행과 시연 동작을 대상으로 했습니다. 장시간 실행의 안정성은 별도 검증이 필요합니다.
