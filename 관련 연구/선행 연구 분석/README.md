## 선행 연구 분석 이유
팀원들 모두 임베디드 기기를 대상으로 펌웨어를 추출하고 분석하거나 수정해 본 경험이 없거나 많지 않았기 때문에
프로젝트를 어떻게 진행해야 하는지 감을 잡기 쉽지 않았습니다. 

그래서 IoT 기기를 대상으로 펌웨어를 추출하고 분석을 하는 논문을 선행 연구로 선정하였습니다.

해당 연구에서 저희 팀원들은 평소 웹이나 일반적인 소프트웨어 프로젝트에서는 접하기 어려웠던 임베디드 기기의 펌웨어가 어떤 구조로 이루어져 있고,
실제 기기의 프로그램을 수정하기 위해서는 어떤 단계를 거처야 하는지 전체적인 흐름을 먼저 이해할 수 있었습니다.

## 선행 연구 분석
### I. 논문 개요
- **문제의식**: IP카메라 등 소형 IoT 기기가 UART/JTAG 등 디버깅 포트를 숨기고 펌웨어 업데이트 파일을 암호화하여, 기존 정적·동적 취약점 분석 방식의 적용이 어려워짐
- **제안 방법**: 기기 구성 환경에 관계없이 동일하게 적용 가능한 플래시 메모리 칩 오프(Chip-Off) 방식으로 펌웨어를 추출하는 범용 방법론 제시
- **대상**: IP카메라 등 소형 IoT 기기에 주로 탑재되는 SOP(Small Outline Package) 타입 플래시 메모리 칩
- **목표**: ① 펌웨어 추출 → ② 셸 환경 활성화(펌웨어 변조) → ③ 동적 분석 환경 구축까지 이어지는 5단계 표준 절차 제시
- **실험 검증**: 중국 JOOAN IP 카메라 실기기 적용 결과, telnet root 셸 획득 및 gdbserver 기반 동적 디버깅 환경 구축에 성공
- **한계**: Secure Boot가 적용된 고가형 기기에는 본 방법론만으로 적용 불가 (글리칭 등 결함 주입 공격과의 결합 필요)
<br><br> 

### Ⅱ. 연구 배경 및 관련 연구
**2.1 배경**<br> 
IoT 시장은 지속적으로 성장하고 있으며, 이에 따라 공격 표면도 확대되고 있습니다. MITRE 조사에 따르면 2015년 이후 발견된 IoT 관련 취약점은 약 1,267건이며 DoS, Sniffing, Spoofing 등이 포함됩니다. 
2016년 Mirai 봇넷 사례는 IoT 기기의 취약한 관리자 계정 설정을 악용해 대규모 DDoS 공격을 일으켜 트위터·넷플릭스 등 1,200여 개 사이트를 마비시킨 대표적 사례입니다. <br> 
취약점 분석의 두 축은 정적 분석과 동적 분석이나, 둘 다 펌웨어 확보 및 분석 환경 구축이 선행되어야 합니다. 그러나 제조사가 펌웨어를 공개하지 않거나 디버깅 포트를 은폐하는 경우가많아 범용적인 가이드라인의 부재가 연구자들의 어려움으로 지적됩니다. <br> <br> 
**2.2 기존 연구와의 차별점**<br> 
**가) 펌웨어 이미지 추출 연구**<br> 
UART·JTAG 포트 활용, 업데이트 패킷 스니핑, 플래시 덤프 등의 기존 연구가 있었으나, 디버깅 포트 은폐 및 업데이트 파일 암호화 시 적용이 어렵고 기기별로 작업 흐름이 달라 범용적 방법론으로 사용하기 힘들었습니다. 본 논문은 기기 구성 환경에 영향받지 않는 플래시 메모리 칩 오프 방식을 채택했습니다. <br> 
**나) 동적 분석 환경 구축 연구** <br> 
Firmadyne, FirmAE 등이 제안되었으나, 기기 의존성과 주변 장치 환경을 모두 설정해야 해 범용 적용에 한계가 있습다. 본 논문은 하드웨어 작업을 통해 실기기에 직접 셸 환경을 구성하는 방법론을 제시합니다.
<br><br> 

### Ⅲ. 제안 방법론: 5단계 프로세스
방법론은 ① Chip-Off → ② Firmware Extraction → ③
Firmware Modify → ④ Rework → ⑤ Testing의 5단계로 구성되며, 분석 환경 구축을 위해 순서대로 수행해야 합니다. <br><br>

**3.1 Chip-Off (칩 탈거)** <br>
PCB에 납땜된 플래시 메모리 칩을 손상 없이 제거하는 단계이며, 유해물질(납·플럭스)과 고열 장비를 사용하므로 보호구 착용 및 환기가 필수적입니다. <br>
**(1) Pre-Work**
1. 기기를 정상 연결하여 앱․웹 UI 등 주요 기능이 정상 작동하는지 사전 확인
2. 케이스 분해 재조립을 위해 분해 순서를 상세히 기록
3. PCB에서 펌웨어가 내장된 칩(플래시 메모리) 식별
4. 칩 표면 인쇄 모델명으로 데이터시트 확보
5. 데이터시트에서 SPI 채널(CS, DO/MISO, WP, GND, VCC, HOLD, CLK, DI/MOSI) 핀 배열 확인 및 매핑표 작성 <br>

**(2) Desoldering**
1. 칩 주변에 플럭스 도포(납 산화 방지, 탈거 용이)
2. 인두기 온도 설정 후 칩 다리 부분에 열을 가하며 탈거 (논문 실험값: 380°C 인두 팁 상태·납 종류에 따라 조정 필요) <br>

**(3) Cleaning**
1. 솔더윅으로 칩․PCB의 잔여 납 제거
2. 이소프로필 알코올 및 플럭스 제거제로 잔여물 세심하게 세척<br>

**3.2 Firmware Extraction (펌웨어 추출)** <br>
**(1) Firmware Read**
1. 데이터시트 기반 SPI 핀 매핑표대로 칩 SPI 핀과 마이크로컨트롤러(라즈베리파이·아두이노) SPI 핀 연결
2. flashrom 오픈소스 툴로 칩 인식 후 펌웨어 이미지 덤프<br>
   flashrom은 수백 종의 플래시 칩·메인보드·프로그래머를 지원하며, 미등록 칩도 데이터시트를 바탕으로 직접 정보를 추가해 사용할 수 있습니다. PCB에서 칩을 떼지 않고 바로 읽는 것도 가능하나, PCB 노이즈로 인해 불완전한 덤프가 발생할 수 있어 Chip-Off 후 추출이 권장됩니다. <br>

**(2) File System Extraction**
binwalk로 덤프 이미지 내부의 파일시스템 시그니처를 탐지·추출합니다.
- binwalk: 파일시스템 및 데이터 구조 탐지·추출 기능 제공, 리패키징 기능 없어 별도 작업 필요
- firmware-mod-kit (fmk): 추출 시 fmk 디렉터리 생성·파일 수정과 재패키징을 함께 지원해 변조 작업에 용이 <br>

**3.3 Firmware Modify (셸 환경 활성화)** <br>
동적 디버깅을 위해서는 셸 환경이 필요하나 일반 사용자용 펌웨어는 기본적으로 비활성화되어 있습니다. 아래 3가지 변조 지점 중 파일시스템 상황에 맞는 방법을 선택합니다.
- 패턴 A. telnetd 활용: 파일시스템에 telnetd 바이너리가 있는 경우, 부팅 스크립트에 telnetd 실행을 추가하고 /etc/shadow를 수정해 telnet으로 root 접속
- 패턴 B. netcat 리버스 셸: nc 명령어가 있으나 네트워크 미연결 가능성이 있는 경우, 특정 서버로 지속 접속을 시도하는 리버스 셸 스크립트를 작성해 부팅 스크립트에서 백그라운드 실행
- 패턴 C. 명령어 정적 삽입: telnetd․nc가 모두 없는 경우, 기기 아키텍처(ARM/MIPS 등)를 확인 후 busybox․socat․nc를 정적 컴파일해 파일시스템에 삽입 (단, 용량 증가로 리패키징에 제약 가능성 존재)<br>
논문 실습 사례(JOOAN 카메라, 패턴 A): 부팅 스크립트에 「/usr/sbin/telnetd &」를 추가하고, /etc/shadow의 root 라인을 「root::10933:0:99999:7:::」 형태로 수정했습니다.
